## CRITICAL

### C1. Signal-mode region (the schema DEFAULT) stops inserting regional ads after its first scheduled/API ad
`engine/RegionProcess.ts:401-405` + `:284` + `RegionManager.ts:86,105,114`.
When an ad finishes naturally, `_playFiles` only returns to master when `returnMode==='playlist_end'`;
for `returnMode==='signal'` (the DB default — "wait for stop signal") it hits a bare `else { return }`,
leaving `adActive=true` and `state.mode='ad'`. `startAd:284` only arms a return timer for
`returnMode==='timer'`. A scheduled or API-triggered ad is NOT bracketed by a stop tone, so the
region waits forever for a signal that never comes: audio recovers to master via the bridge fade,
but `state.mode` stays `ad`, DB `status='ad'`, ICY metadata frozen on the ad title, dashboard wrong —
and `handleTone('start')` filters `state.mode==='main'`, so **the region is excluded from every
subsequent tone-triggered ad insertion** until a manual return. Net: a default-config region silently
stops taking regional ads after its first scheduled ad — the product's core function fails, quietly.
Tone-triggered ads are safe (the `:260-268` return timer rescues them).
**Fix:** in `_playFiles`, when an ad finishes with `returnMode==='signal'` and no stop-signal is
pending (non-tone trigger), call `returnToMain('completed')` like the `playlist_end` path — or arm a
return for `signal`+non-tone triggers in `startAd`. At minimum always reset `adActive`/`state.mode`
to main when the ad audio ends and nothing will send a stop tone.

## HIGH

### H1. No per-role authorization — viewer/operator can mutate everything, including stream credentials
`index.ts:84-91` + all routers. `requireRole` is applied ONLY in `users.ts` (`requireRole('admin')`).
Every other router — `regions`, `playlists`, `settings`, `schedules`, `region-schedules`, `reports` —
is mounted with `requireAuth` alone. A `viewer` (intended read-only) or `operator` can create/delete
regions, **rewrite Icecast credentials and `source_url` via `PUT /api/settings`**, delete playlists,
trigger ads, take regions off-air. The 3-role model is cosmetic outside user management. New since the
prior audit (which covered authN, not per-role authZ).
**Fix:** `requireRole('admin')` on `settings` (holds secrets) + `users`; `requireRole('admin','operator')`
on the mutating verbs of `regions`/`playlists`/`schedules`/`region-schedules`; allow GET for `viewer`.
Gate per-method or split read/write mounts.

### H2. Non-tone ad has no playback timeout — a hung ad ffmpeg wedges the region permanently
`engine/RegionProcess.ts:370` / `IcecastSource.ts:295-356`. `feedFile`'s promise resolves only on the
ad ffmpeg `exit` event. Only `tone` triggers get the `:260` return timer that SIGKILLs a stuck ad; for
`api`/`schedule` there is no upper bound. A corrupt concat entry / zero-byte upload / stuck `-re` read
leaves `_playFiles` awaiting forever, `adLocked` stuck true, the region in ad mode indefinitely —
accepts no further ads.
**Fix:** arm a hard max-duration watchdog for every trigger type (sum(durations)+slack, or a ceiling),
SIGKILL+resolve on expiry like the tone path.

## MEDIUM

### M1. Non-transactional ad logging + no orphan reaper → over-counted proof-of-play
`RegionProcess.ts:86-99, 256-257`. `logAdStart` INSERTs `status='running'`, `logAdEnd` UPDATEs later
in a separate query, no transaction, and there is no startup sweep of stale `running` rows (verified
absent in index.ts/RegionManager.ts). A crash/redeploy mid-ad (exactly when an ad is on air) leaves a
zombie `running` row with `end_time=NULL`. The campaigns report counts `COUNT(al.id)` including
zombies → over-reports delivered plays to the advertiser. The fast re-trigger at :256 (interrupt-then-
start) is also non-atomic.
**Fix:** (1) on engine start, `UPDATE ad_logs SET status='interrupted', end_time=COALESCE(end_time,start_time) WHERE status='running'`;
(2) wrap interrupt-then-start in a transaction; (3) exclude/segregate `running` from advertiser totals.

### M2. Report day-bucketing uses UTC, not station local time → day-boundary mismatches
`routes/reports.ts:52,62,26-27,60-61,76-77`. `DATE(al.start_time)` and the `$::date` range bounds have
no `AT TIME ZONE`, and no `TZ` is pinned anywhere (no env). On a UTC DB session, every ad aired
00:00–03:00 Kyiv is bucketed into the previous calendar day, and a 23:30-Kyiv play on the "to" date can
be excluded. Advertiser reconciliation against the local log mismatches at day edges.
**Fix:** `DATE(al.start_time AT TIME ZONE 'Europe/Kyiv')` for grouping and the same conversion on range
predicates; make the zone a setting.

### M3. Duplicate `ad_end` webhook/Telegram on signal-mode regions
`RegionProcess.ts:384-393` vs `:420-430`. Natural completion fires `ad_end`, then a later
manual/stop-tone `returnToMain` fires it again. Operators get two "ad ended" alerts per ad.
**Fix:** emit from one place, or guard the second with `if (this.state.adLogId)`.

### M4. Relay backup→primary failback is stochastic (25%/exit) — region can ride backup long after master recovers
`IcecastSource.ts:281-282`. On backup, each relay exit returns to primary only when `Math.random()<0.25`;
a stable backup never exits, so the master is never re-probed — a region can stay on backup audio for
hours/days after the master is healthy, with no time-based recheck.
**Fix:** periodic primary re-probe (every N min) instead of relying on random exits.

### M5. `transmitter_ip` / `lat` / `lng` stored with no validation
`routes/regions.ts:92,119`. Stored verbatim (parameterized — no SQLi; `pingOnce` re-validates the IP, so
no command injection). Junk silently fails ping; lat/lng unbounded.
**Fix:** `net.isIP()` (allow empty) + numeric-range bound lat/lng in `validateRegionInput`.

## LOW
- **L1** `regions.ts:161-167,204-211` — `trigger`/`assignments` accept unvalidated `playlist_id` FKs (500 via global handler instead of clean 400/404). Parse positive-int + existence-check.
- **L2** `reports.ts:190-205` — XLSX export ignores the report's from/to filters (always last-30d/2000-rows) and silently truncates with no notice; times written as `toLocaleString` TEXT (not Excel datetimes). Param by from/to (bounded span), stream rows, write Date cells with numFmt.
- **L3** `frontend/api.ts` + AuthContext — a 401 on a LATER request doesn't redirect to login (refresh runs only on mount); user gets stuck on error toasts. Centralize 401 → set unauthenticated.
- **L4** `RegionProcess.ts:234-253` — `state.mode='ad'` set before campaign/freq/empty guards → brief phantom "ad" in a concurrent getStatus. Defer assignment until after guards.
- **L5** `ToneDetector.ts:42`/`SilenceWatchdog.ts:42` — 50 Hz bandpass @ -20 dB can false-negative on a low/short cue tone; calibration risk, make threshold/width configurable.
- **L6** `regions.ts:152` — `stop failed: ${e.message}` returned to client (operator-only path).
- **L7** `reports.ts:31-34` — region-filtered campaigns report lists 0-play playlists ambiguously ("ran but nothing" vs "not assigned").
- **L8** `ui.tsx:381` — Sparkline regenerates a `Math.random()` gradient id every render (new `<defs>` each paint; harmless).
